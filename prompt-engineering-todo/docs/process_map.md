# Карта процесса работы с языковой моделью (Process Map)
Версия: 1.1 (актуализирована по результатам аудита Q01)

## Таблица шагов

| Шаг | Название и функция | Обязательный вход (источник) | Ожидаемый выход | Контрольная точка (КТ) и проверка человеком | Условие перехода (Успех / Возврат) |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **Шаг A** | Аудит процесса и согласование требований | Требования R01–R10 (v1.0), ограничения Java 17, проект карты | Замечания аудитора в отдельном чате | **КТ1 (Человек):** Ручной анализ замечаний, формирование таблицы решений | **Успех:** Замечания обработаны, требования и карта обновлены до v1.1 -> переход к Шагу B. |
| **Шаг B** | Генерация тестовых сценариев | Актуальные требования R01–R10 (v1.1) | Таблица >=8 сценариев (ID, вход, точный ожидаемый вывод, тип: позитивный/негативный/граничный) + матрица покрытия | **КТ2 (Человек):** Проверка полноты покрытия R01–R10, наличие >=3 граничных случаев | **Успех:** Все правила покрыты, матрица готова -> переход к Шагу C. **Возврат:** Неполное покрытие -> уточняющий запрос на тесты. |
| **Шаг C** | Генерация кода программы | Требования v1.1, сценарии тестов, технические ограничения | Исходный код `TodoListApp.java` и команды запуска | **КТ3 (Человек):** Проверка имени файла, отсутствия package, компиляция `javac -encoding UTF-8`, подсчет строк (50-150) | **Успех:** Код компилируется, нет package, 50-150 строк -> переход к Шагу D. **Возврат:** Ошибки компиляции -> повторный запрос кода. |
| **Шаг D** | Прогон сценариев и анализ расхождений | Код `TodoListApp.java`, сценарии тестов | Логи запусков в `evidence/`, карточка расхождений | **КТ4 (Человек):** Посимвольное сравнение stdout, пустой stderr, exit code 0 | **Успех:** Все тесты пройдены -> переход к Шагу F. **Дефект:** Обнаружено расхождение -> оформление карточки дефекта, переход к Шагу E. (Если ошибка в сценарии -> возврат к Шагу B). |
| **Шаг E [Условный]** | Локальное исправление дефекта | Код, карточка дефекта (вход, ожидание, факт), затронутое Rxx | Локальный исправленный метод и пояснение | **КТ5 (Человек):** Проверка локальности правки, лимит 2 попытки, проверка объема (50-150 строк) | **Успех:** Упавший тест пройден -> возврат к Шагу D для полного регресса. **Лимит исчерпан:** Остановка модели, ручное исправление человеком с фиксацией в журнале. |
| **Шаг F** | Подведение итогов и приёмка | Финальный код, логи всех запусков, заполненная матрица | Итоговый акт приёмки программы | **КТ6 (Человек):** Проверка всех критериев DoD | **Вердикт:** Принято / Принято с ограничениями -> сборка отчета и архива. |
