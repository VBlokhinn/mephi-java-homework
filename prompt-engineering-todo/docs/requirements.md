# Постановка задачи: Список дел в памяти (Todo List In-Memory)
Версия: 1.1 (актуализирована по результатам аудита Q01)

## 1. Паспорт проекта
- **Тема:** Консольное приложение "Список дел в памяти" (`TodoListApp.java`).
- **Назначение:** Управление списком задач в рамках одной сессии через текстовые команды.
- **Среда выполнения:** Java 17, стандартная библиотека, без `package`, кодировка UTF-8.
- **Объём кода:** от 50 до 150 строк (без пустых строк и комментариев).

## 2. Границы учебной версии
- **Входит:**
  - Хранение задач в оперативной памяти (in-memory) до завершения процесса.
  - Нумерация задач натуральными числами с 1 до N.
  - Статусы задачи: активна `[ ]`, выполнена `[X]`.
  - Команды: `add <текст>`, `list`, `done <id>`, `remove <id>`, `exit`.
- **Исключено:**
  - Сохранение на диск/в БД, дедлайны, приоритеты, теги, многопоточность, сетевые интерфейсы, GUI.

## 3. Спецификация требований R01–R10 (v1.1)
- **R01:** Программа размещена в файле `TodoListApp.java`, не содержит объявления `package`, компилируется и запускается на Java 17 (UTF-8), используя только стандартную библиотеку. Объём кода - от 50 до 150 строк.
- **R02:** Модель задачи включает целочисленный ID (от 1 до N), текстовое описание и логический статус выполнения (по умолчанию не выполнена). При удалении задачи оставшиеся задачи перенумеровываются (номера образуют непрерывный ряд от 1 до текущего размера списка).
- **R03:** По команде `add <текст>` создается задача. Текст задачи обрезается по краям (`trim()`), внутренние пробелы сохраняются. Если текст пуст или состоит только из пробелов, выводится строка `ERROR: EMPTY_TASK`. При успехе выводится строка `ADDED <id>` (через одиночный пробел).
- **R04:** По команде `list` выводится нумерованный список в формате `<id>. [ ] <текст>` или `<id>. [X] <текст>` (по одной строке на каждую задачу). Если список пуст, выводится ровно одна строка `EMPTY`.
- **R05:** По команде `done <id>` задача переводится в выполненные, выводится `DONE <id>` (через одиночный пробел). Если задача уже была выполнена ранее, статус не меняется, выводится `ALREADY_DONE <id>`.
- **R06:** По команде `remove <id>` задача удаляется, выводится `REMOVED <id>` (через одиночный пробел). Оставшиеся задачи перенумеровываются с 1 до N.
- **R07:** Если аргумент `<id>` в командах `done` или `remove` не является натуральным числом либо отсутствует, выводится `ERROR: INVALID_ID`. Если номер отсутствует в текущем списке (id < 1 или id > N), выводится `ERROR: NOT_FOUND`.
- **R08:** Команды чувствительны к регистру (строчные). Пустые строки ввода игнорируются. На любую нераспознанную команду или лишние аргументы у команд `list`/`exit` выводится ровно одна строка `ERROR: UNKNOWN_COMMAND`.
- **R09:** Программа завершает работу по команде `exit` (выводит `BYE` и немедленно завершает работу) либо при наступлении конца потока ввода EOF (завершает работу молча, без вывода `BYE`).
- **R10:** Программа не выводит приглашений ко вводу (`> `) и приветствий. Каждому действию соответствует строго одна строка ответа, кроме команды `list`, выводящей по одной строке на каждую задачу (или строку `EMPTY`, если список пуст).

## 4. Критерии завершения (Definition of Done)
1. Код компилируется на Java 17: `javac -encoding UTF-8 TodoListApp.java` и запускается: `java TodoListApp`.
2. Код укладывается в 50–150 строк (без пустых строк и комментариев).
3. Проведено не менее 8 сценариев тестирования финальной сборки (среди них не менее 3 граничных).
4. Каждое требование R01–R10 покрыто тестами.
5. Разобран минимум один сбой (с ограничением не более 2 попыток исправления моделью).
6. Заполнен журнал запросов, подготовлен handoff-пакет, составлен акт приёмки.
